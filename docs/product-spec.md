# 경주 배지 수집 Wear OS 앱 — 제품 사양 (v0.1)

작성일: 2026-10-31 · 상태: 초안(첫 구현 범위 확정)

## 1. 한 줄 요약

경주의 명소와 맛집을 **실제로 방문**하면 손목 위에서 바로 배지를 받는, 워치 단독(standalone) Wear OS 앱.

## 2. 대상 사용자와 가치

| 대상 | 상황 | 얻는 가치 |
| --- | --- | --- |
| 경주를 도보·자전거로 돌아보는 여행자 | 휴대폰을 꺼내기 번거로운 이동 중 | 손목에서 주변 장소를 확인하고 방문을 인증, 수집 재미로 동선 확장 |
| 가족·친구 단위 방문객 | 아이와 함께 유적지 탐방 | 배지 수집이라는 명확한 목표로 탐방 동기 부여 |

## 3. 범위

### 3.1 v0.1 포함 (전체 제품 목표)

- 앱에 **내장된 경주 장소 데이터**(명소·맛집) 열람
- 주변 장소 확인 → 장소 상세 → **사용자가 직접 방문 인증 요청**
- 현재 위치 1회 측정으로 방문 검증(규칙은 [check-in-rules.md](check-in-rules.md))
- 장소별 **1회만** 배지 지급, 획득 기록은 기기 내 Room DB에 저장
- 앱 재실행·재부팅 후에도 배지 기록 유지
- 획득한 배지 목록 열람

### 3.2 v0.1 제외 (명시적 비범위)

회원가입/로그인, 서버·동기화, 휴대폰 컴패니언 앱, 결제, 랭킹·소셜, **상시(백그라운드) 위치 추적**, 푸시 알림, 다국어(한국어만), 워치페이스/컴플리케이션, 타일.

### 3.3 첫 구현 범위 (이번 작업)

문서 작성 후 구현은 아래 한 흐름으로 **제한**한다.

> **장소 1개 표시 → 위치 인증 → 배지 지급 → 로컬 저장(재실행 후 유지)**

- 장소 목록·검색·주변 장소 정렬·배지 목록 화면은 다음 단계로 미룬다.
- 데이터 모델과 인증 로직은 전체 범위를 수용할 수 있게 설계하되, UI는 장소 1개(첨성대)만 노출한다.

## 4. 핵심 사용자 흐름

```
[주변 장소 확인] → [장소 상세] → (인증 버튼) → [위치 권한 확인]
      → [현재 위치 측정 (≤20초)] → [규칙 검증] → [배지 지급 + 저장] → [결과 표시]
                                                        ↘ 실패 시 사유 표시 (재시도 가능)
[앱 재실행] → [획득 배지 유지 확인]
```

첫 구현에서는 `[주변 장소 확인]`을 "장소 1개 상세 화면"으로 대체한다.

### 4.1 화면 (첫 구현)

| 화면 | 구성 요소 | 동작 |
| --- | --- | --- |
| 장소 상세 겸 인증 화면 | 장소명, 분류(명소/맛집), 짧은 설명, 상태 문구, 하단 EdgeButton "방문 인증" | 버튼 → 권한 확인/요청 → 인증 → 결과 문구 |
| 결과 상태(같은 화면) | "배지 획득!", "이미 획득한 배지", 실패 사유 | 실패 시 버튼 재활성화 |

### 4.2 상태 표시 문구 (사용자에게 보이는 결과)

| 결과 | 문구(안) |
| --- | --- |
| 배지 획득 | "배지를 획득했어요! 🏅" |
| 이미 획득 | "이미 획득한 배지예요" |
| 권한 거부 | "위치 권한이 필요해요. 설정에서 허용해 주세요" |
| 낮은 정확도 | "위치 정확도가 낮아요(±NNm). 하늘이 보이는 곳에서 다시 시도해 주세요" |
| 오래된 위치 | "위치 정보가 오래됐어요. 다시 시도해 주세요" |
| 시간 초과 | "위치를 찾지 못했어요(20초). 다시 시도해 주세요" |
| 범위 밖 | "장소에서 NNNm 떨어져 있어요. 더 가까이 가주세요" |
| 위치 사용 불가 | "지금은 위치를 가져올 수 없어요" |

## 5. 비기능 요구사항

- **오프라인 우선**: 네트워크 없이 모든 기능 동작(장소 데이터 내장, Room 저장).
- **배터리**: 위치는 사용자가 버튼을 눌렀을 때만 1회 요청. 상시 추적 없음.
- **성능**: 인증 요청 후 20초 이내 결과 표시(시간 초과 포함).
- **접근성/가독성**: 원형 소형 화면 기준, Wear Material 3 컴포넌트 사용, 글자 1~2줄.
- **개인정보**: 위치는 인증 판정에만 사용하고 기기 밖으로 전송하지 않음. 획득 시 좌표를 기록(현장 검증·디버깅용)하되 사용자 요청 시 삭제 가능해야 함(다음 단계).

## 6. 플랫폼·기술 결정

| 항목 | 결정 | 근거(공식 문서) |

| UI | Kotlin + Compose for Wear OS **Material 3**(`androidx.wear.compose:compose-material3`) | [Compose for Wear OS setup](https://developer.android.com/training/wearables/compose) — Material 3 권장, `compose-material`과 혼용 금지 |

| SDK | compileSdk 37 / targetSdk 37 / minSdk 30(Wear OS 3+) | [Wear OS 7 setup](https://developer.android.com/training/wearables/versions/7/setup), Compose 1.12는 compileSdk 37·AGP 9 요구 |

## 7. 성공 기준 (첫 구현)

1. 에뮬레이터/실기기에서 장소 1개가 표시된다.
2. 장소 좌표 근처(에뮬레이터 위치 시뮬레이션)에서 인증 시 "배지 획득" 상태가 된다.
3. 같은 장소를 다시 인증하면 위치 측정 없이 "이미 획득" 상태가 된다.
4. 앱을 종료 후 재실행해도 획득 상태가 유지된다.
5. 권한 거부·낮은 정확도·시간 초과·범위 밖 각각에 대해 정의된 문구가 표시된다.
6. 인증 규칙 로직은 Android 의존성 없는 모듈에서 단위 테스트로 검증된다.

## 8. 미결 사항

- 장소 데이터의 좌표·반경은 **현장 검증 전 임시값**이다(각 장소 `verified=false`).
- 맛집 데이터 출처·갱신 정책(앱 업데이트로만 갱신).
- GPS 없는 워치(휴대폰 위치 의존)에서의 정확도 실측치.
